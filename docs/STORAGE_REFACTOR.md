# 환자 저장·파일 정리 리팩토링 — 2026-10-25

## 범위와 호환성

리뷰 후 사용자 지시(“수정 후 리팩토링”)에 따라 저장 안전성 수정과 책임 분리를 진행했다.
AsyncStorage 키 `ems-log.current-patient.v1`, workspace version 2, `FormState`·`PatientWorkspace`의 필드,
첨부파일·신분증·필기의 저장 디렉터리는 유지한다. 기존 단일 환자 데이터의 마이그레이션도 유지한다.
새 저장 스키마나 버전 변경이 없으므로 별도 데이터 변환은 필요하지 않다.

## 동작

- `patientWorkspace.ts`: 기존 타입·초깃값·마이그레이션과 복구 검증.
- `patientStorage.ts`: 하나의 환자 workspace, 직렬 저장 큐, 자동 저장, 명시적 저장·삭제·초기화.
- `usePatientWorkspace.ts`: React 구독과 백그라운드 전환 시 대기 중 저장 실행.
- `identityCapture.ts`: 가이드 기준 자르기·다중 OCR, 등록 성공 후 원본·중간 이미지 정리.
- `patientFileCleanup.ts` / `usePatientFileCleanup.ts`: 파일 정리 실패 추적, 재시도 안내와 앱 복귀 시 재시도.

복구가 실패하면 입력·저장·초기화를 막고 재시도 화면을 표시한다. 테마 읽기 실패는 환자 복구와 독립적이다.
신분증·필기 삭제와 신분증 교체는 먼저 저장소에 반영하고 나서 이전 파일을 지운다.
전체 초기화는 앞선 저장 뒤에 실행하고, 최신 workspace에서 파일 목록을 얻은 뒤 저장 성공 후 정리한다.
저장 실패 시 기존 화면과 파일을 보존하며, 파일 정리 실패는 기록 변경 실패와 구분해서 알린다.
다른 환자가 참조하는 공유 파일은 지우지 않는다.

## 검증과 한계

필수 타입 검사·린트·Node 테스트로 복구 실패, 재시도, 느린 저장 중 입력·환자 전환,
삭제 시 저장 실패, 초기화 순서, 파일 정리 재시도, OCR 등록 실패 시 정리를 확인한다.
기존 소스 문자열 테스트는 분리된 실제 모듈을 검사하도록 옮겼다.

실기기의 저장 공간 부족·권한 오류·카메라/ML Kit·백그라운드 종료는 별도 확인이 필요하다.
백그라운드 저장 요청은 OS에 의해 강제 종료되기 전 완료를 보장하지 않는다.
파일 정리 재시도 목록은 메모리에 유지되므로 앱 프로세스가 종료되면 미정리 파일의 재시도 상태는 사라진다.
영구적인 정리 작업 기록이나 파일 전수 정리는 저장 정책 변경을 포함할 수 있어 이번 범위에 넣지 않았다.
이 변경은 소스 수정 범위이며, APK 빌드·설치·릴리스 배포는 포함하지 않는다.
