# 약 봉투 분석 (ChatGPT 연동) 설계 — 2026-11-01

상태: 구현함(2026-11-01). 실기기 확인 전. 빌드·설치하지 않음.

## 목적

과거력 확인 중 약전 없이 약 봉투만 있을 때, 대원 본인의 ChatGPT(유료 구독)로 약물명, 부작용, 추정 병력을 빠르게 확인한다. 앱은 서버나 API를 쓰지 않으므로 비용이 들지 않는다.

## 사용자 결정

- 분석은 각 대원의 ChatGPT 앱으로 한다. API는 쓰지 않는다.
- 결과는 약물명, 부작용, 추정 병력 3개 항목만 받는다. 사무적인 개조식으로 받는다.
- 환자 이름은 보내지 않는다.
- 개인정보를 자동으로 찾아 가리는 방식(OCR 마스킹)은 놓칠 수 있다. 그래서 **사용자가 보낼 영역을 직접 지정**하는 방식을 기본으로 한다.
- 프롬프트의 "개인정보 기재 금지" 문장은 답변에 개인정보가 다시 나오지 않게 하는 보조 장치다. 사진이 보내지는 것 자체를 막지는 못한다.

## 흐름

1. **진입**: 하단 "약물" 탭의 "복용 약물" 구간에 "처방전 촬영 · ChatGPT 분석" 버튼을 둔다(2026-11-01 "약 봉투"에서 문구 변경). 녹취나 촬영 중에는 비활성화한다.
2. **촬영 또는 앨범**: `expo-camera`로 찍거나, 촬영 화면 왼쪽 "앨범" 버튼으로 시스템 사진 선택기(`expo-image-picker`)에서 고른다. 저장소 권한은 쓰지 않는다(`blockedPermissions` 유지). 카메라 권한이 없어도 앨범은 쓸 수 있다. 원본은 캐시 디렉터리에만 두고 환자 기록에 저장하지 않는다.
3. **영역 지정**: 사진 위에 사각형 틀을 띄운다. 모서리 4개를 끌어 크기를 바꾸고, 틀 안을 끌어 옮긴다. 처음 틀은 약 목록 모양에 맞춰 가로 80%, 세로 45%로 가운데에 둔다. 틀 바깥은 어둡게 표시한다. 두 손가락 확대는 넣지 않았다. 가까이 찍도록 촬영 화면에서 안내한다.
4. **추가 가리기(선택)**: 확인 화면에서 잘린 사진 위에 "가리기" 펜으로 문질러 검게 칠한다. 되돌리기와 모두 지우기가 있다. 잘린 사진 위에서 칠하므로 보이는 그대로 보내진다.
5. **사본 만들기**: 촬영 직후 사진을 똑바로 세운 JPEG로 다시 저장해 EXIF(위치, 기기 정보)를 없앤다. `expo-image-manipulator`로 원본 좌표 기준으로 자르고 긴 변을 2048px 이하로 줄인다. 좌표는 안쪽으로 반올림해 틀 바깥 픽셀이 들어가지 않는다. 칠한 획이 있으면 `react-native-view-shot`으로 미리보기 화면 자체를 JPEG로 찍어 보낸다. 모든 처리는 기기 안에서 하고 네트워크를 쓰지 않는다.
6. **미리보기**: 실제로 보낼 사본만 크게 보여 준다. 안내 문구: "이 사진만 ChatGPT로 보내집니다. 이름·병원명이 보이면 돌아가서 가려 주세요." 버튼은 "다시 지정"과 "ChatGPT로 보내기"다.
7. **전송**: Android `ACTION_SEND`로 사본(`EXTRA_STREAM`, FileProvider content URI, `FLAG_GRANT_READ_URI_PERMISSION`)과 프롬프트(`EXTRA_TEXT`)를 넘긴다. 패키지는 `com.openai.chatgpt`로 고정한다.
   - ChatGPT가 설치되지 않았으면 "ChatGPT 앱이 필요합니다"라고 안내하고 Play 스토어 링크를 띄운다.
   - 전송 버튼은 대원이 ChatGPT 안에서 직접 누른다. 다른 앱의 전송을 대신 누를 수는 없다.
8. **정리**: 모든 임시 파일은 캐시의 `medicine-bag/` 폴더 하나에만 둔다. 닫을 때, ChatGPT에서 앱으로 돌아왔을 때(AppState active), 다음 분석을 시작할 때, 앱을 켤 때 폴더째 지운다. 환자 기록에는 아무것도 저장하지 않는다.

## 프롬프트

목표는 매번 같은 형식의 답을 받는 것이다. 그래서 출력 틀과 예시를 보여 주고, 틀 밖의 문장을 금지하고, 판독에 실패했을 때 쓸 문장을 정해 둔다.

2026-11-01 사용자 지시로 형식을 바꿨다. 예전에는 약물명, 부작용, 추정 병력을 1·2·3번으로 나눴다. 이제는 약을 **진료과별로 묶고**, 각 약 옆에 **추정 병력을 바로** 적는다. 부작용은 약 아래 한 줄로 남겼다.

- 진료과 목록은 `MEDICINE_DEPARTMENTS` 상수로 고정한다: 심혈관계, 호흡기, 신경과, 정신건강의학과, 내분비(당뇨·갑상선), 소화기, 신장내과, 비뇨기과, 정형외과, 기타. ChatGPT는 이 이름만, 이 순서로 쓰고, 약이 없는 과는 생략한다.
- 한 약이 여러 과에 걸치면 주된 용도의 과 한 곳에만 쓴다.
- 추정 병력은 1~2개만 쓴다. 위장약·진통제처럼 병력을 특정할 수 없으면 "병력 특정 어려움"이라고 쓴다.

```text
출력 형식
■ 진료과
- 약품명 (성분명) → 추정 병력
  부작용: 주요 부작용 1줄

예시
■ 심혈관계
- 노바스크정 (암로디핀) → 고혈압
  부작용: 하지 부종, 어지럼
```

- 프롬프트 전문은 `src/medicineBagPrompt.ts`에 있다. 테스트는 진료과 틀, 과 목록, 판독 불가 문장이 들어 있는지 확인한다.
- 같은 프롬프트라도 답은 대원 계정의 모델과 설정(맞춤 지침, 메모리)에 따라 조금 달라질 수 있다. 형식 틀과 예시가 이 차이를 줄인다. 실제 답은 실기기에서 확인한다.

## 기술 메모

- 사용 라이브러리: `expo-camera`, `expo-image-picker`(앨범, 2026-11-01 추가), `expo-image-manipulator`, `react-native-view-shot`, `react-native-svg`.
- 공유: 기존 `expo-sms` 패치처럼 `setPackage`가 필요하다. React Native 기본 `Share`는 패키지를 고정할 수 없어 공유 시트가 뜬다. 로컬 Expo 모듈 `modules/chatgpt-share`(자동 연결)로 구현했다. Android 11 이상의 패키지 조회용 `<queries>`는 모듈의 AndroidManifest에 넣어 병합되므로 `app.json`은 바꾸지 않았다.
- ChatGPT가 `EXTRA_TEXT`를 입력칸에 채우지 않는 버전이면 프롬프트가 빠진다. 이 경우를 위해 같은 로컬 모듈이 전송 직전 프롬프트를 클립보드에도 복사하고(새 의존성 없음), 미리보기에 "입력칸이 비어 있으면 길게 눌러 붙여넣기"라고 안내한다.
- 권한: 카메라 외에 새 권한이 없다. 앱은 계속 인터넷을 쓰지 않는다. 전송은 ChatGPT 앱이 한다.
- iOS: 모듈이 없으므로 시스템 공유 시트(`Share.share`)에서 ChatGPT를 고르게 한다. 현재 배포 대상이 Android라 실기기 확인은 후순위다.
- 이 모듈이 들어가기 전 빌드에서는 "앱을 업데이트해 주세요"라고 안내한다.
- 구현 파일: `src/MedicineBagAnalysis.tsx`(화면), `src/medicineBagCrop.ts`(좌표 계산), `src/medicineBagFiles.ts`(임시 파일), `src/medicineBagPrompt.ts`, `modules/chatgpt-share/`. 진입 버튼은 `src/PatientNoteScreen.tsx`의 약물 탭. 테스트는 `scripts/test-medicine-bag.cjs`.

## 하지 않는 것

- OCR 자동 마스킹(놓칠 수 있어 기본에서 제외)
- 결과를 앱으로 다시 가져와 저장하기(ChatGPT 앱 결과를 읽을 방법이 없고, 저장 범위가 늘어난다)
- 식약처 공공데이터 API 대조(인터넷 권한과 키 관리가 필요하다. 별도 결정)

## 실기기 확인 항목

- 사진과 프롬프트가 ChatGPT 입력칸에 함께 들어가는지(삼성 기기, ChatGPT 최신 버전)
- 실제 처방전·약 봉투 5~10장에서 답이 진료과별 형식을 지키는지, 과 이름이 목록 밖으로 나가지 않는지, 판독 불가 문장이 나오는지
- 잘린 사본에 틀 바깥이 남지 않는지, 칠한 부분이 사본에 반영되는지
- 앱으로 돌아온 뒤 캐시 파일이 지워지는지
- 로컬 모듈의 Kotlin 코드가 컴파일되는지(빌드하지 않아 확인하지 못함)
